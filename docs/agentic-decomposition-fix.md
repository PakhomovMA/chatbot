# Составной вопрос в AGENTIC: разработчик подменялся брендом

Воспроизведение 2026-09-08 на работающем сервисе с `qwen3:14b`, EmbeddingGemma и существующим
Lucene-индексом: 2 документа, 75 chunks. Вопрос: «Какая длина контекста у GLM-5.3 и кто разработал Kimi-K3?».

До исправления AGENTIC ответил: «Длина контекста у GLM-5.3 составляет 1M токенов.
Kimi-K3 разработан компанией Kimi.», `PARTIAL`, без citations, 35.2 с.
Трасса: `dc826056-bcfc-4b36-83cd-98e2c683006d`; один vector search, пять passages.
В них есть контекст GLM и «Kimi's most capable flagship model», но нет указания разработчика.

Причины:

- `decompose.enabled=true` выбирал GOAP-действие только на DETERMINISTIC-пути; AGENTIC пропускал разбор.
- Инструкция предлагала начать с целого вопроса. Модель сочла найденный бренд достаточным ответом
  и не уточнила вторую часть поиском.
- Verifier проверяет принадлежность citations найденным passages, а не логическое следование каждого
  утверждения из текста. `PARTIAL` не удалял неподтверждённое утверждение.

Повтор DETERMINISTIC в этой сессии также выдал «компанией Kimi», уже с `GROUNDED` и ссылкой
на passage с possessive brand name. Поэтому правильный ответ в предыдущем прогоне не доказывает,
что проблема ограничена выбором retrieval-режима.

В оригинале загруженного `kimi-k3.md` Moonshot присутствует в `MOONSHOT_API_KEY`,
`api.moonshot.ai` и URL изображений. Прямого утверждения о разработчике нет. Эти технические
идентификаторы сами по себе не подтверждают отношение «разработан компанией».
Пользовательский корпус не дополнялся и не переиндексировался.

Изменения:

- При включённом разборе составной вопрос в AGENTIC проходит существующую декомпозицию и hybrid
  retrieval по вопросу и частям. Отказ/сбой разбора сохраняет имеющийся fallback на одиночный поиск.
- Модель получает merged evidence в пределах `evidence-char-budget`, с chunk IDs, и сохраняет
  доступ к ToolishRag для уточнений. Только реально показанные начальные passages попадают в collector;
  повторные tool hits дедуплицируются с ними. `decomposition` сохраняется в итоговой диагностике.
- Инструкции требуют проверять каждую часть отдельно и явно сообщать о недостающих отношениях.
  Общие grounding rules различают бренд, разработчика и технические идентификаторы.
- Ответ по найденным passages без citations, включая неполный, один раз формируется заново по bounded numbered
  evidence. Исходное предположение не передаётся в повторный prompt и не отправляется в SSE.
  Если модель всё ещё заявляет достаточность без валидных citations, возвращается безопасный `INSUFFICIENT_EVIDENCE`.
  Дополнительный вызов измеряется как `chatbot.llm{operation=repair-agentic-answer}`.

На исходном корпусе после исправления получен ответ: «Длина контекста у GLM-5.3 составляет 1M токенов [8].
Разработчик Kimi-K3 не указан в предоставленных документах [2].», `INSUFFICIENT_EVIDENCE`, две citations,
48.5 с, два подвопроса в диагностике. Это ожидаемый результат для источника без явного подтверждения
разработчика. Чтобы требовать именно Moonshot AI в grounded-ответе, корпус должен содержать такое
утверждение из подходящего источника.

Ограничение: наличие валидной ссылки по-прежнему не является автоматической семантической проверкой
всего ответа. Исправление обеспечивает retrieval по частям, уточняет grounding-инструкции и закрывает
выдачу достаточного, но полностью нецитированного ответа; оно не обещает исключить любые ошибки LLM.

Проверки:

- `./gradlew clean build`: 267 backend tests и 14 frontend tests, без failures и skips.
  Новые hermetic tests проверяют выбор AGENTIC-пути с декомпозицией, citations из начального evidence,
  объединение с tool results без повторов, границу evidence budget, literal untrusted text,
  повторное формирование достаточного и неполного ответа, отклонение phantom citations и ответ без поиска.
- Живой `POST /api/chat/stream` на исходном корпусе: стадии `decomposing → retrieving → researching`,
  один итоговый delta, `verifying`, `final`; 48.5 с, две citations, `INSUFFICIENT_EVIDENCE` с notes о разработчике.
- `bootRun`: обнаружен `qwen3:14b`, `/actuator/health` — `UP`, индекс `READY`, 2 документа / 75 chunks.
  SHA-256 обоих originals совпадает с исходной metadata.
- `./gradlew test -PincludeTags=e2e --tests '*AgenticDecompositionE2eTest'`: 2/2, без skips,
  72 с. В отдельном временном корпусе с явным разработчиком получено «Kimi-K3 был разработан Moonshot AI [2]»
  вместе с контекстом GLM [1], `GROUNDED`. Для вымышленного Lyra-R7 с одной possessive brand phrase —
  контекст GLM [1], разработчик не указан [2], `INSUFFICIENT_EVIDENCE`, проверен SSE final.
  Первоначальный прогон выявил потерю citations у неполного ответа; повторное формирование расширено
  на этот случай, и оба теста прошли после исправления.
