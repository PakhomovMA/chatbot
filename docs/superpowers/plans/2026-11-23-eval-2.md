# Eval 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an 18-document, 160-question retrieval eval with multi-chunk relevance, calibrated chunking/sufficiency and paired statistical comparison of EmbeddingGemma v1/v2.

**Architecture:** Keep the existing Lucene/parser/retrieval path and specialized eval sets. Extract multi-relevance scoring, fixture validation and calibration into small testable components; keep real model execution in `RagEvalTest`. Produce per-question JSON and a dependency-free paired-bootstrap Markdown report.

**Tech Stack:** Java 25, JUnit 5, AssertJ, Jackson 3 (`tools.jackson.*`), existing Tika/Lucene/ONNX/Ollama integration, Python standard library via `uv run`.

**Spec:** `docs/superpowers/specs/2026-11-23-eval-2-design.md`

## Global Constraints

- Do not change public `/api` DTOs, architectural invariants or pinned dependency versions.
- Do not add production or Python package dependencies; PDFs are committed fixtures generated locally.
- Preserve every existing primary question and ID; specialized `hard`, `conversation` and `multipart` sets stay separate.
- Use 18 documents and at least 160 primary questions (224 after the statistical-power expansion), at least 40 multi-chunk and at least 25% of the final set (62/224), 12 comparisons, 12 RU→EN and 12 EN→RU.
- Use chunk candidates 500/800/1200 with overlap 100; equivalence margins are ±0.02 and bootstrap uses 10,000 resamples with a fixed seed.
- Do not modify or delete user data under `~/.chatbot`; eval uses temporary indexes.
- Do not run git-mutating commands unless the user explicitly asks for them.

## Review Focus

- PDF/table extraction inserts whitespace or drops layout: expected phrases must survive the real parser, checked by `EvalFixtureTest.allExpectedPhrasesSurviveParsing`.
- A multi-chunk label collapses into one chunk at selected chunking: checked by `EvalFixtureTest.multiChunkQuestionsHaveDistinctChunks`.
- One hit matching several labels inflates nDCG: checked by `EvalMetricsTest.aHitIsCountedOnlyOnce`.
- Reports with missing/duplicate/mismatched question IDs cannot form valid pairs: checked by comparison script unit tests.
- A metric with no applicable questions must not divide by zero or fabricate a CI: checked by `EvalMetricsTest` and comparison script empty-input tests.
