# Ревью Phase 9d — 2026-09-08

Проверен commit `15f74753eb9fadd3a5ff92c265c747a19dbd4cff` и приложенный `docs/report.md`.
Основная реализация соответствует плану: выбор действий через GOAP, retrieval через детерминированный
сервис, системные инструкции отдельно от недоверенных данных, сравнение использует нумерацию evidence,
обе новые ветки выключены по умолчанию. Найдены и исправлены ошибки в обработке результатов модели,
слиянии проходов, отмене и diagnostics.

## Исправления

1. **Повторы подвопросов ошибочно считались разбиением.** Проверка «не менее двух частей» выполнялась
   до удаления дублей и повторения исходного запроса. Ответ модели `["rollback", "ROLLBACK"]` запускал
   дополнительные проходы и блокировал `expandSearch`, хотя самостоятельная часть была одна.
   Теперь очистка и дедупликация без учёта регистра происходят до лимита и проверки числа частей.
   Пустые, чрезмерно длинные (> 1000 символов) и содержащие управляющие символы запросы отбрасываются;
   они не занимают места полезных частей. Если осталось меньше двух, выполняется обычный поиск.

2. **Слабый первый score скрывал сильное совпадение по подвопросу.** При повторном обнаружении чанка
   сохранялись только scores первого прохода. Например, cosine 0.2 для вопроса целиком перекрывал
   cosine 0.8 для его части: evidence ошибочно оставались ниже порога достаточности 0.5.
   Теперь каждый facet сохраняет максимальный score среди проходов, а ранжирование остаётся RRF.
   Это исправляет и общий механизм `expandSearch`.

3. **Соседние чанки дублировались или терялись при слиянии.** Сосед, найденный в нескольких проходах
   либо у нескольких hits, несколько раз занимал бюджет evidence. Обратный случай: сосед полностью
   исчезал, если другой проход обнаружил его как hit, который затем не вошёл в итоговый `topK`.
   Теперь каждый чанк выводится один раз; hits внутри итогового `topK` сохраняют собственный rank,
   остальные доступные соседи сохраняются как контекст соответствующего выбранного hit.

4. **Завышалось время decomposition.** Общий helper повторно добавлял время первого прохода к wall time,
   уже включавшему все параллельные проходы. Теперь caller передаёт полное время явно: для decomposition
   оно совпадает с `decomposition.tookMs`, для expansion включает предшествовавший одиночный поиск.

5. **Отмена не проверялась внутри параллельных retrieval-задач.** При ограничении concurrency оставшиеся
   задачи могли начать поиск после отключения клиента. Теперь сигнал проверяется до и после каждого
   прохода и перед возвратом evidence; отмена не запускает fallback. Уже выполняющийся поиск завершается
   до ближайшей проверки сигнала — принудительное прерывание Lucene/ONNX не добавлялось.

6. **Один `null` обнулял полезное сравнение.** `null` в списке аспектов вызывал исключение, после которого
   best-effort fallback удалял весь результат. Теперь некорректные элементы и пустые названия аспектов
   пропускаются отдельно, а допустимые выводы сохраняются вместе с проверенными номерами пассажей.
